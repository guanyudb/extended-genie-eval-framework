Genie evaluation at scale, built natively on Databricks

A working reference implementation of a SQL-grounded evaluation framework for Genie agents. It evaluates beyond the 500-benchmark limit, reports health per core question, and updates ground truth once per core question with a selective re-run.

core questions→variations→validation→Genie→compare→triage→health→fix & re-run
Built and run on synthetic pharma-commercial data with fictional brands (TRx / NRx by brand, territory, rep, quarter) Use ← → to move between slides

Starting point

A custom evaluation pipeline, and what it needs from the platform

Teams running Genie in production often build an evaluation pipeline like this one. A commercial analytics team can need 1,000 to 1,500 benchmark questions per agent, and that number grows with every new market and brand. A Genie agent holds up to 500.

A typical custom evaluation pipeline

  1. Core Q&A set: business questions with validated ground-truth SQL
  2. Python script generates phrasing variations (paraphrase, typos, shorthand)
  3. Validation suite stores core questions and variations in Delta
  4. MLflow evaluate pipeline sends each question to Genie and runs both SQLs
  5. Result DataFrames are compared
  6. LLM-as-a-judge checks semantic equivalence
  7. Diagnostic report classifies failures and recommends fixes
  8. Data scientists update instructions and re-evaluate the agent

What it needs from the platform

Evaluate more than 500 questions per agentKeep the full benchmark set running as markets and brands are added.
Core-question healthSee accuracy per core question, not only one overall score, so underperforming questions stand out.
Bulk ground-truth updateUpdate ground-truth SQL once per core question, propagate it to every variation, and re-evaluate only those.
Run it fully on DatabricksReplace the externally hosted LLM report step with governed, native capabilities.

What we saw

SQL-grounded variations from one SQL statement

The model reads each ground-truth query, extracts its semantic contract, and writes one variation per category. The output lands in Delta.

In a custom pipeline

Stage 2, a Python script that writes phrasing variations, calling an LLM through an external gateway.

On Databricks

ai_query('system.ai.claude-sonnet-4-6', …) runs inside SQL, row by row, over the core table. Calls are recorded in the Unity Gateway usage table with requester and tokens.

What we saw

  • 64variations across 8 categories, generated in a single statement
  • 0generation errors (errors are captured per row with failOnError => false)

Watch for

Claude models reject responseFormat => '{"type":"json_object"}' in ai_query. Ask for raw JSON in the prompt and extract it with regexp_extract. Generate variations once and persist them; never re-generate on read.

CREATE OR REPLACE TABLE {{schema}}.variations_raw AS
WITH gen AS (
  SELECT core_id, arguments,
    ai_query(
      '{{model}}',
      concat(
        'You generate benchmark question variations to stress-test a text-to-SQL agent for a pharma commercial team. ',
        'Parse the ground-truth SQL to extract its semantic contract (metric, filters, time period, grouping). ',
        'Return ONLY a raw JSON object (no markdown) {"variations":[{"category":"...","question":"..."}]} with exactly one variation for EACH category: ',
        'paraphrase, conversational, contextual_pronoun, time_variation, shorthand_typo, edge_case_short, filter_sensitivity, adversarial. ',
        'Rules: all categories except filter_sensitivity and adversarial MUST keep the exact same semantics as the SQL. ',
        'time_variation must refer to the SAME period differently (e.g. "April through June 2026" for 2026-Q2). ',
        'contextual_pronoun uses I/me/my only if a sales_rep_id argument exists, otherwise refers to "our team". ',
        'filter_sensitivity changes exactly one filter value. adversarial is ambiguous or tricky phrasing. ',
        'Core question: ', question, '\nArguments: ', coalesce(arguments, 'none'), '\nGround-truth SQL: ', gt_sql),
      failOnError => false,
      modelParameters => named_struct('temperature', CAST(0.7 AS DOUBLE), 'max_tokens', 1500)
    ) AS r
  FROM {{schema}}.core_questions
)
SELECT core_id, arguments, v.category, v.question, r.errorMessage AS gen_error
FROM gen
LATERAL VIEW explode(from_json(regexp_extract(r.result, '(?s)\\{.*\\}', 0), 'STRUCT<variations: ARRAY<STRUCT<category: STRING, question: STRING>>>').variations) AS v

Step 03 of 12 · Build the benchmark

Validate every variation with ai_decide()

Three structured decisions per row, each with a probability. A variation enters the benchmark only if the ground-truth SQL still answers it.

In a custom pipeline

Stage 3, the variation validation suite: semantic equivalence, argument mapping, ambiguity, and category tagging.

On Databricks

Betaai_decide()noul · choice

noul questions return a probability (is it equivalent? is it ambiguous?). A choice question returns the category with per-label probabilities and a confidence. Thresholds route each row to valid, invalid, or needs review.

What we saw

  • 57/72accepted into the benchmark (64 variations plus 8 originals)
  • 8/8filter-changing variations rejected
  • 7/8adversarial variations rejected; the eighth really was equivalent
  • ~2.5 minfor all 72 rows in one SQL statement, including cold start

CREATE OR REPLACE TABLE {{schema}}.variations
COMMENT 'Benchmark variations validated with ai_decide(). Ground truth is inherited from core_questions via core_id.'
AS WITH src AS (
  SELECT c.core_id, c.question AS core_question, c.arguments, c.gt_sql, 'original' AS category, c.question AS question
  FROM {{schema}}.core_questions c
  UNION ALL
  SELECT v.core_id, c.question, c.arguments, c.gt_sql, v.category, v.question
  FROM {{schema}}.variations_raw v
  JOIN {{schema}}.core_questions c USING (core_id)
),
decided AS (
  SELECT *,
    ai_decide(
      to_json(named_struct('core_question', core_question, 'runtime_arguments', coalesce(arguments, 'none'),
                           'ground_truth_sql', gt_sql, 'candidate_variation', question)),
      '{
        "equivalent": {"type": "noul",
          "instructions": "Is the ground-truth SQL a fully correct answer to the candidate variation, i.e. the variation asks for the same metric, the same filters and filter values, the same time period and the same grouping? Treat typos, abbreviations, informal phrasing and equivalent date ranges (e.g. April through June 2026 = 2026-Q2) as equivalent. Pronouns like I/me/my refer to the runtime argument sales_rep_id."},
        "ambiguous": {"type": "noul",
          "instructions": "Is the candidate variation ambiguous enough that a competent analyst could reasonably write materially different SQL for it?"},
        "category": {"type": "choice",
          "instructions": "Which variation style best describes the candidate relative to the core question?",
          "criteria": {"original": "Identical to the core question",
                       "paraphrase": "Reworded with the same meaning",
                       "conversational": "Informal, chatty phrasing",
                       "contextual_pronoun": "Uses I/me/my/our to refer to the user context",
                       "time_variation": "Refers to the same time period in a different way",
                       "shorthand_typo": "Contains typos, abbreviations or poor grammar",
                       "edge_case_short": "Very short or terse keyword-style phrasing",
                       "filter_sensitivity": "Changes one filter value so the meaning differs",
                       "adversarial": "Ambiguous, multi-part or tricky phrasing"}}
      }'
    ) AS d
  FROM src
)
SELECT
  concat(core_id, '-', lpad(cast(row_number() OVER (PARTITION BY core_id ORDER BY category = 'original' DESC, category) - 1 AS STRING), 2, '0')) AS test_id,
  core_id, question, arguments, category AS generated_category,
  d:response.answers.category.choice::STRING            AS decided_category,
  round(d:response.answers.equivalent.probability::DOUBLE, 3) AS p_equivalent,
  round(d:response.answers.ambiguous.probability::DOUBLE, 3)  AS p_ambiguous,
  round(d:response.answers.category.confidence::DOUBLE, 3)    AS category_confidence,
  CASE WHEN d:error_message IS NOT NULL AND d:error_message::STRING IS NOT NULL THEN 'error'
       WHEN d:response.answers.equivalent.probability::DOUBLE >= 0.8 AND d:response.answers.ambiguous.probability::DOUBLE < 0.5 THEN 'valid'
       WHEN d:response.answers.equivalent.probability::DOUBLE < 0.3 THEN 'invalid'
       ELSE 'needs_review' END AS status,
  d:error_message::STRING AS decide_error
FROM decided

Step 04 of 12 · Build the benchmark

Sync benchmarks from Delta into the Genie agent

A sync job rebuilds the agent's benchmark list from the validated table and replaces only that section of the agent configuration.

In a custom pipeline

Usually not a separate stage. It is what lets the native benchmark tooling run on a Delta master set instead of hand-entered benchmarks.

On Databricks

GAGenie agent management APIserialized_space

get_space returns the full configuration, the job swaps benchmarks.questions, and update_space writes it back. Data sources, instructions, and joins are untouched. Benchmark IDs are derived from test_id, so they stay stable across syncs.

What we saw

  • 57benchmarks synced; instructions and join specs preserved on every update
  • 500benchmark limit per agent, enforced in the job before it writes

Watch for

IDs are 32-character hex, unique across sample questions and benchmarks, and arrays are sorted by ID. The whole configuration must stay under 3.5 MB, with at most 25,000 characters per string.

MAX_BENCHMARKS = 500  # documented per-agent limit


def build_benchmarks(core_ids: list[str] | None = None) -> tuple[list[dict], list[dict]]:
    where = f"AND v.core_id IN ({','.join(sql_str(c) for c in core_ids)})" if core_ids else ""
    rows = sql(f"""
        SELECT v.test_id, v.core_id, v.question, v.arguments, c.gt_sql
        FROM {SCHEMA}.variations v JOIN {SCHEMA}.core_questions c USING (core_id)
        WHERE v.status = 'valid' {where}
        ORDER BY v.test_id""")
    if len(rows) > MAX_BENCHMARKS:
        raise SystemExit(f"{len(rows)} benchmarks > {MAX_BENCHMARKS}; sync in batches (by core_id) instead")
    questions, mapping = [], []
    for r in rows:
        text = r["question"] + (f" (context: {r['arguments']})" if r["arguments"] else "")
        bid = bench_id(r["test_id"])
        questions.append({"id": bid, "question": [text],
                          "answer": [{"format": "SQL", "content": [r["gt_sql"]]}]})
        mapping.append({"test_id": r["test_id"], "core_id": r["core_id"], "benchmark_id": bid,
                        "gt_sql_hash": hashlib.md5(r["gt_sql"].encode()).hexdigest()})
    return sorted(questions, key=lambda q: q["id"]), mapping
def main() -> None:
    benchmarks, mapping = build_benchmarks()
    state = load_state()
    if "space_id" not in state:
        space = w.genie.create_space(
            warehouse_id=WAREHOUSE_ID, serialized_space=json.dumps(initial_space(benchmarks)),
            title="[POC] Pharma Commercial Rx - Genie Eval Framework",
            description="Reference implementation (synthetic data). Benchmarks synced from Delta core_questions/variations.")
        state = save_state(space_id=space.space_id)
        print(f"created space {space.space_id}")
    else:
        current = w.genie.get_space(state["space_id"], include_serialized_space=True)
        payload = json.loads(current.serialized_space)
        payload["benchmarks"] = {"questions": benchmarks}
        w.genie.update_space(state["space_id"], serialized_space=json.dumps(payload))
        print(f"updated benchmarks on space {state['space_id']}")
    write_mapping(mapping)
    synced = json.loads(w.genie.get_space(state["space_id"], include_serialized_space=True).serialized_space)
    print(f"benchmarks in space: {len(synced.get('benchmarks', {}).get('questions', []))} (expected {len(benchmarks)})")
    print(f"text instructions preserved: {bool(synced.get('instructions', {}).get('text_instructions'))}")

def benchmark_ids(core_ids: list[str]) -> list[str]:
    rows = sql(f"""SELECT benchmark_id FROM {SCHEMA}.benchmark_map
                   WHERE core_id IN ({','.join(sql_str(c) for c in core_ids)})""")
    return [r["benchmark_id"] for r in rows]


def run_eval(space_id: str, ids: list[str] | None) -> tuple[str, float]:
    t0 = time.time()
    run = w.genie.genie_create_eval_run(space_id, benchmark_question_ids=ids)
    while True:
        r = w.genie.genie_get_eval_run(space_id, run.eval_run_id)
        status = r.eval_run_status.value if r.eval_run_status else None
        print(f"{time.time() - t0:5.0f}s {status} {r.num_done}/{r.num_questions}", flush=True)
        if status not in ("RUNNING", "NOT_STARTED"):
            return run.eval_run_id, time.time() - t0
        time.sleep(20)


def fetch_results(space_id: str, run_id: str) -> list[dict]:
    results, token = [], None
    while True:
        page = w.genie.genie_list_eval_results(space_id, run_id, page_size=100, page_token=token)
        results += page.eval_results or []
        token = page.next_page_token
        if not token:
            break
    with ThreadPoolExecutor(8) as pool:
        details = list(pool.map(
            lambda r: w.genie.genie_get_eval_result_details(space_id, run_id, r.result_id).as_dict(), results))
    return details

Step 06 of 12 · Evaluate

An MLflow harness with no benchmark cap

Each question is a traced Genie call through the Conversation API. Scorers run on every row, and per-core pass rates are logged as MLflow metrics.

In a custom pipeline

Stage 4, the MLflow evaluate pipeline: read the question, send it to Genie, run both SQLs, store results, track everything in MLflow.

On Databricks

GAGenie Conversation APIMLflow 3 · mlflow.genai.evaluateMLflow Tracing

predict_fn asks Genie and fetches the result rows. Three scorers (result match, ai_decide triage, recommended fix) attach feedback to each trace. Ground truth runs once per core question and is reused for every variation.

What we saw

  • 45/57passed (79%), with the same two weak core questions as the native run
  • 6 minfor 57 questions with 4 workers (9.5 per minute in our workspace)
  • 18.4 smedian Genie response time; 24.9 s at p90

Watch for

Conversation API throughput is limited per workspace and shared by every Genie agent there. The harness retries with exponential backoff. Size throughput for 1,500-question runs with your account team.

@mlflow.trace(span_type="TOOL")
def ask_genie(question: str) -> dict:
    for attempt in range(6):
        try:
            msg = w.genie.start_conversation_and_wait(SPACE_ID, question)
            break
        except Exception as e:  # rate limits / transient errors: exponential backoff
            if attempt == 5:
                return {"status": "ERROR", "error": str(e)[:500], "genie_sql": None, "columns": [], "rows": []}
            time.sleep(min(60, 2 ** attempt * 3))
    out = {"status": msg.status.value if msg.status else None, "genie_sql": None, "columns": [], "rows": [],
           "error": msg.error.error if msg.error else None, "text": None,
           "conversation_id": msg.conversation_id, "message_id": msg.message_id}
    for att in msg.attachments or []:
        if att.text and att.text.content:
            out["text"] = att.text.content
        if att.query and att.query.query:
            out["genie_sql"] = att.query.query
            res = w.genie.get_message_attachment_query_result(SPACE_ID, msg.conversation_id, msg.message_id,
                                                              att.attachment_id)
            sr = res.statement_response
            if sr and sr.manifest and sr.result:
                out["columns"] = [c.name for c in sr.manifest.schema.columns]
                out["rows"] = (sr.result.data_array or [])[:MAX_ROWS]
    return out


@mlflow.trace(span_type="AGENT")
def predict_fn(question: str, test_id: str, core_id: str) -> dict:
    t0 = time.time()
    out = ask_genie(question)
    out["latency_s"] = round(time.time() - t0, 1)
    return out
def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--core-ids", nargs="*")
    ap.add_argument("--limit", type=int)
    ap.add_argument("--workers", default="4")
    ap.add_argument("--run-name", default="genie-eval-harness")
    args = ap.parse_args()
    os.environ["MLFLOW_GENAI_EVAL_MAX_WORKERS"] = args.workers
    mlflow.set_tracking_uri(f"databricks://{PROFILE}")
    mlflow.set_experiment(EXPERIMENT)

    data = build_dataset(args.core_ids, args.limit)
    print(f"{len(data)} questions, workers={args.workers}")
    t0 = time.time()
    with mlflow.start_run(run_name=args.run_name) as run:
        res = mlflow.genai.evaluate(data=data, predict_fn=predict_fn,
                                    scorers=[result_match, failure_triage, recommended_fix])
        elapsed = time.time() - t0
        persist(run.info.run_id)
        # Core-question health logged as MLflow metrics as well
        per_core = sql(f"""SELECT core_id, round(avg(CASE WHEN passed THEN 1 ELSE 0 END), 3) AS pass_rate, count(*) n
                           FROM {SCHEMA}.harness_results WHERE run_id = {sql_str(run.info.run_id)} GROUP BY core_id""")
        mlflow.log_metrics({f"core_{r['core_id']}_pass_rate": float(r["pass_rate"]) for r in per_core})
        mlflow.log_metrics({"questions": len(data), "elapsed_s": round(elapsed),
                            "questions_per_min": round(len(data) / (elapsed / 60), 2)})
    print(f"run_id={run.info.run_id} elapsed={elapsed:.0f}s qpm={len(data)/(elapsed/60):.2f}")
    for r in sorted(per_core, key=lambda x: x["core_id"]):
        print(r)

def _norm(v):
    if v is None:
        return "null"
    try:
        return str(round(Decimal(str(v)), 1).normalize())
    except InvalidOperation:
        return str(v).strip().lower()


def compare(gt_rows: list, genie_rows: list) -> str:
    gt = Counter(tuple(sorted(_norm(v) for v in r)) for r in gt_rows)
    ge = Counter(tuple(sorted(_norm(v) for v in r)) for r in genie_rows)
    if gt == ge:
        return "match"
    if len(gt_rows) == len(genie_rows) and gt_rows:
        # Genie returned the GT values plus extra columns (e.g. extra dimension/label) -> partial
        ge_sets = [set(_norm(v) for v in r) for r in genie_rows]
        if all(any(set(_norm(v) for v in g) <= s for s in ge_sets) for g in gt_rows):
            return "partial"
    return "mismatch"


@scorer
def result_match(outputs: dict, expectations: dict) -> list[Feedback]:
    if not outputs.get("genie_sql") or outputs.get("status") != "COMPLETED":
        label = "error"
    else:
        label = compare(expectations["gt_rows"], outputs["rows"])
    return [Feedback(name="result_match", value=label,
                     rationale=f"gt_rows={len(expectations['gt_rows'])} genie_rows={len(outputs.get('rows') or [])}"),
            Feedback(name="passed", value=label in ("match", "partial"))]
